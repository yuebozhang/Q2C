# SSS 实施路线

状态：计划，尚未实现。建立日期：2026-11-05。

## 1. 验证消息提交入口

- 核对指定任务能否通过 Codex 深链接打开。
- 比较 Accessibility 操作输入框与受支持的程序接口。
- 程序接口能恢复会话，不等于已验证能控制桌面 App 中同一个任务；需分别验证任务身份、可见性和并发状态。
- 先用合成内容验证定位和填入，不自动提交真实客户文本。

退出条件：可可靠识别目标任务与输入框；遇到其他任务、未发送草稿或无法确定状态时能够停止。

## 2. 快捷键与消息包装

- 建立 Swift macOS 菜单栏应用。
- 用户按快捷键时读取文本剪贴板，保留完整换行与原文。
- 使用正式标识 `$sss`，以“客户说”标记客户数据；不要求每次选择平台或会话编号。
- 目标任务作为本机配置，不硬编码进源文件或提交个人任务 ID。
- 处理空剪贴板、非文本、连续按键及目标未就绪。

退出条件：能正确包装多行、特殊字符和客户引用中的命令字；不覆盖用户已有草稿。

## 3. 提交与反馈

- 定位与填入验证通过后，再启用明确触发的提交动作。
- 区分待发送、已提交、执行中、完成及失败。
- 有界队列与重复触发保护；目标忙碌时排队或提示，不能盲目打断已有工作。
- 超时先核实是否已经提交，防止重发。

退出条件：错误路由和重复发送测试通过，失败有可理解提示。

## 4. 后续扩展

按实际使用反馈增加：结果通知、打开回复、可选复制回复、快捷键与目标设置、应用签名和发布。
